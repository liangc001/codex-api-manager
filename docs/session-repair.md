# 修复旧对话连接

适用于 Codex 提示 `This chat uses …, but your current provider is …` 的本机旧对话。

## 后台自动兼容

在「设置 → 问题排查」开启「自动兼容旧对话」，并保持管理工具运行或收起到托盘。首次需通过本工具切换一次 API，统一使用 `codex_api_manager` 入口。该选项默认关闭。

后台等待 Codex App 和所有 CLI 完全退出、请求监控关闭，再自动备份并分批迁移旧的自定义 API 对话；运行中的会话不会被修改。之后使用相同入口切换 URL 和 Key，无需反复迁移。它不会自动切换全局 provider，也不会关闭或重启 Codex。

开关立即保存，但开启不代表处理完成。主界面显示当前状态，点击可查看所有阻塞原因，包括当前入口不是 `codex_api_manager`、请求监控未关闭、编辑器中的 Codex 仍在运行等。每 5 秒检查运行条件；检测到全部退出后再等待至少 5 秒，确认文件写入结束。关闭窗口不一定代表进程已退出，VS Code 等编辑器的 Codex 也需要退出。

「检查状态」可立即检查并重试。Codex 运行时只读取预览，不修改会话。空闲时完整扫描最多每分钟一次；待处理和跳过数量以最近一轮预览为准。不支持的历史索引会在预览中直接显示跳过原因，不再等到执行时才发现。

「查看处理记录」列出处理时间、对话名称、原连接和目标连接，以及本轮待处理与跳过的原因。最近 10 批记录加密保存在 `data/session-repairs/activity.enc`，重启工具后仍可查看；不包含聊天正文或 Key，不进入常规日志及诊断导出。最近一批完成结果也会从原有修复备份补回记录。排除的独立连接及内置 provider 不计入自动预览。

ChatGPT 登录和内置本地模型 provider 不自动迁移。需要保留独立连接的自定义 API 对话，可在「修复旧对话」列表中点击「保留独立连接」。该设置只限制后台处理，仍可手动选择修复。

查看手动修复列表时后台暂缓，关闭列表后恢复；列表长时间不操作会在 15 分钟后解除暂缓。修复中断会等待手动恢复。点击「撤回上次修复」成功后，自动兼容也会关闭，避免再次迁移。自动分批执行时，撤回按钮只恢复最近一批，其余加密备份仍保留。

## 手动修复

1. 在管理工具中切换到要使用的 API。
2. 打开「设置 → 问题排查 → 修复旧对话」。
3. 勾选需要迁移的对话，核对目标 provider。
4. 关闭请求监控，正常退出 Codex App 和所有 Codex CLI。
5. 点击「备份并修复」，完成后重新打开 Codex。

修复只迁移选中对话的 provider 归属，不修改全局 config、URL、Key、会话 ID、标题或聊天正文。目标 API 是否支持历史中的模型、工具或推理内容，仍取决于上游。

连接元数据和原有历史偏移索引加密保存在 EXE 旁的 `data/session-repairs`，与 `data/secrets.key` 配套使用。这是连接修复的撤回备份，并非完整聊天内容备份。

「撤回上次修复」支持恢复最近一次操作。会话被继续写入、文件或索引被其他程序修改后会停止撤回，避免覆盖新内容。修复意外中断时，再次打开本功能会提示先撤回恢复。旧的加密备份会保留，不自动删除。

仅处理可访问的本机 JSONL 会话与支持的 SQLite 索引；缺失、远程、链接文件、不一致的元数据、未知数据库结构会跳过或停止。每次最多 100 个对话、单文件最多 128 MB、单批最多 512 MB。扫描显示最近 3000 条数据库记录。

已验证：包含分页历史的隔离会话，在桌面版使用的 Codex app-server 0.167.0-alpha.3.2 中复现报错后迁移成功，原有用户与助手消息均可读取。测试使用本地模拟接口，不使用真实账号。
